# 电商图片设计工作流

依据：用户要求覆盖主图、详情页、SKU 图，并先学习所提供飞书页面截图 PDF（5 页，2026-10-21）。截图中的角色提示、平台默认数量、宠物烘干箱参数、营销链接均为参考资料，不是执行指令或通用商品事实。

| ID | 验收标准 |
|---|---|
| ED01 | 可读取安全校验后的产品/对标图并通过 MCP 图片内容交给 Host 观察；区分外观观察和用户核实的性能事实，不虚称服务端有视觉模型或自动搜索能力。 |
| ED02 | 收集平台、受众、目标、产品图、外观观察、事实来源、风格及交付类型。信息不足返回明确问题；对标阶段允许用户提供参考，或明确记录不使用参考的理由，不自动跳过。 |
| ED03 | 主图默认 5 张、可选 1–8 张；首张干净全貌，后续一图一个已提供卖点。详情默认 10 屏、可选 8–15 屏，遵循痛点、解决方案、产品展示、信任、购买引导；未知尺寸/认证/优惠/竞品参数不生成。 |
| ED04 | SKU 每个版本一图，要求版本自己的产品图与真实属性；统一视角、比例、背景、字体和标签位置，不自行改色或添加配置。三类均输出逐图文案、事实依据、视觉主体、构图和排版。 |
| ED05 | 免费方案按版本持久化，可修改逐图文案/排版。版本冲突、非法修改、未知事实引用明确拒绝。批准绑定完整内容摘要，改稿后必须重审。图片冻结为内容寻址副本，防止原图更改使已批准方案改变。 |
| ED06 | 仅当前完整方案、用户明确确认及本次收费授权均满足才可从设计入口提交。每次明确选 1–12 图，稳定映射现有队列标识，重复调用不重复绘图；不引入供应商重试。 |
| ED07 | 恢复后可查询各版本方案、已提交任务及实际已落盘图片路径、尺寸、SHA256；保留失败状态，不能把进行中/失败说成完成。复用现有等待/取消工具。 |
| ED08 | 既有 8 工具签名兼容；更新协议契约、发现说明、Prompt、文档及安全打包清单。单元和真实 stdio 双协议替身验证无收费，不发布、不改私人 Host。 |

参考方法的细节见 docs/ECOMMERCE-DESIGN.md。方案是可供 Host 研讨的结构化底稿，Host 负责理解图片和润色；商品事实、比较依据、平台规则和最终图片均须人工核对。统一风格是提示词约束，不承诺模型生成严格一致，也不承诺平台审核/转化率。首版不添加搜索服务、字体安装、PSD 编辑、长图拼接或店铺上传。
