# 实施方案

保留本机SQLite，默认5个worker共享事务抢占，单次上限统一20。账本增量增加稳定provider_key、参考摘要、请求尝试、恢复尝试、响应检查点路径/摘要及可重试标记。WAL/FULL与busy_timeout继续用于短元数据事务，文件数据不放数据库大字段。

Provider在成功响应解析后调用任务内部检查点钩子，先把响应来源写成带SHA256的本地文件并提交recovering状态，再下载和保存。恢复中的工作可安全重排；owner租约失效只重放已检查点响应，running无响应仍unknown。自动安全重试有次数与退避上限，显式retry不改变请求内容或幂等键。

新增integrity.py处理内容寻址输入、原子输出与文件校验。损坏输出只有显式repair_files授权后才移入隔离备份并用原响应修复，原成功摘要仍约束修复结果。新增可选reference_sha256参与新请求指纹；未传该字段时按旧规范构造指纹，保留旧记录的重复提交行为。

复刻编译依据实际三模型家族/接口/分辨率分档，移除旧模型导向，保持图片角色与完整控制结构。专项测试覆盖5并发同步/20项异步、进程竞争、旧账本兼容、连接/GET/落盘恢复、哈希变动及未知请求禁止重试。用至少200项替身负载实测SQLite，再决定数据库方案。

## Windows CI 修复方案

SQL 追踪定位重复 DDL 与 WAL 收尾；按物理文件缓存成功迁移，worker 生命周期保留无读事务的只读连接并 finally 释放。Windows fixture 记录实际 PID，清理等待进程句柄。新增定量和异常清理回归，不修改 FULL 持久性、业务契约或测试截止。
